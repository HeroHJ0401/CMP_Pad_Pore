# CMP Pad 개공율 분석기_정현진

CMP 패드 표면 SEM 이미지를 이진화하여 개구부를 분할하고, 원형도·solidity·**개공률(open-pore fraction)** 을 산출하는 데스크톱 프로그램입니다.

이미지를 창에 끌어다 놓으면 계산됩니다. Python 설치는 필요 없습니다.

---

## 2. 분석 파이프라인

논문에 기술한 절차와 동일합니다.

```
그레이스케일 정규화
  → Gaussian 평활 (σ = 1.2 px)
  → 이진화 (임계 모드에 따라 고정값 또는 Otsu로 결정, 아래 참조)
  → 형태학적 opening (disk r = 2 px)
  → 연결 성분 라벨링
  → 등가직경 2 µm 미만 객체 제외
  → 프레임 접촉 객체 제외
  → 원형도 = 4πA/P² , solidity = A / A_convex hull
  → 개공률 = (solidity ≥ 0.90 인 객체의 면적 합) / 시야 면적
```

### 용어

| 표시 | 뜻 |
|---|---|
| Pore 수 | 필터를 통과한 Pore 개수 |
| Pore 개공율 | 전체 Pore 면적 / 시야 면적 |
| **유효 Pore 개공율** | solidity ≥ 기준인 면적 / 시야 면적 — **주 지표** |
| 무효 Pore 개공율 | solidity < 기준인 면적 / 시야 면적 |
| Pore 면적(필터전) | 이진화 직후의 어두운 영역. 필터를 걸기 전 |
| Non-Pore 면적 | Pore가 아닌 밝은 영역 = 100 − Pore 면적(필터전) |
| Pore 원형도 | 4πA/P² 의 중앙값 |
| 유효 Pore 원형도 | solidity = A/A_convex hull 의 중앙값 |
| 유효 / 무효 Pore 비율 | 개수 기준 비율. 둘을 더하면 100 % |

**유효 + 무효 = Pore 개공율** 이 항상 성립하므로 세 값이 서로 검산됩니다.

### 왜 단순 암부면적률을 쓰지 않는가

단순히 어두운 픽셀의 비율을 세면 **결론과 반대 방향**이 나옵니다. 어두운 영역에는 노출된 기공뿐 아니라 찢긴 리가먼트 사이의 **그림자**가 섞여 있어, 표면이 거칠수록 값이 커지기 때문입니다.

이 프로그램은 두 값을 모두 보여줍니다.

- `유효 Pore 개공율` — 유효 Pore 원형도(solidity) 기준을 통과한 Pore만 합산한 **주 지표**
- `Pore 개공율` — 검출된 전체 Pore 면적. **유효 + 무효**와 같습니다
- `무효 Pore 개공율` — 기준 미만이라 제외된 면적. 그림자와 폐색 개구부
- `Pore 면적(필터전)` — 이진화 직후의 Pore 후보 영역. SEM에서 구멍은 어둡게 찍히므로 **어두운 영역이 곧 Pore 후보**입니다
- `Non-Pore 면적 %` — Pore가 아닌 밝은 영역

`Pore 면적(필터전)`에서 opening·최소 등가직경·프레임 접촉 필터를 거치면 `Pore 개공율`이 됩니다. 예: 7.24 % → 7.13 %, 차이 0.11 %p가 필터에서 떨어져 나간 양입니다. `Pore 면적(필터전) + Non-Pore 면적 = 100 %`입니다.

### 절대값 사용에 대한 경고

임계값과 solidity 기준을 바꾸면 개공률 **절대값은 크게 변합니다**. 동일 설정에서 두 조건을 비교한 **대소 관계와 비율**만 사용하시고, 절대값을 인용하실 때는 반드시 측정 조건을 병기하십시오.

`강건성 스윕` 버튼이 임계 0.35–0.65 × solidity 0.85–0.95의 21개 조합을 계산해 주므로, 순서가 뒤집히지 않는지 직접 확인하실 수 있습니다.

## 3. 사용법

### GUI

1. 이미지를 창에 끌어다 놓거나, `이미지 추가` 클릭, 또는 **`Ctrl+V`(맥은 `⌘V`)로 붙여넣기** (여러 장 동시 가능)
2. 픽셀 크기는 메타데이터에서 자동으로 채워집니다. 비어 있거나 틀리면 `스케일바로 측정…`
3. 여러 조건을 비교하신다면 `권장 설정`을 누르십시오 (대비 정규화 + Otsu 일괄 + 지형 분할)
4. `분석 실행`
5. `CSV 저장` / `오버레이 저장` / `강건성 스윕`

오버레이 색:

- **녹색** — solidity 기준을 통과해 개공률 분자에 들어간 볼록 개구부
- **적색** — 기준 미만이라 제외된 오목·폐색 개구부
- **파란색** — 프레임에 닿아 계산에서 완전히 빠진 것
- **보라색** — 최소 등가직경보다 작아 빠진 것

분할이 타당한지 눈으로 먼저 확인하십시오.

버리는 기준은 이 둘뿐입니다. **solidity는 버리는 기준이 아닙니다** — 낮으면 빨간색(무효)이 될 뿐 `Pore 개공율`에는 그대로 들어가고, `유효 Pore 개공율`에서만 빠집니다.

| 색 | 판정 | 계산에서 |
|---|---|---|
| 초록 | solidity ≥ 기준 | 유효·전체 모두 포함 |
| 빨강 | solidity < 기준 | 전체에만 포함 |
| 파랑 | bounding box가 네 변 중 하나에 닿음 | 완전히 제외 |
| 보라 | 면적 < π × (최소 등가직경 ÷ 픽셀 크기 ÷ 2)² px | 완전히 제외 |

검사 순서는 보라 → 파랑입니다. 작으면서 경계에도 닿았으면 보라로만 집계됩니다. 그리고 이 판정은 평활·이진화·opening을 모두 거친 뒤에 합니다.

> 파랑·보라는 예전에 칠하지 않던 것입니다. 그래서 "못 찾았다"와 "찾았는데 버렸다"가 화면에서 구별되지 않았습니다. 실제 패드 이미지에서 파란 영역이 **시야의 40.7 %** 였습니다.
>
> **화면 한가운데가 파래도 놀라지 마십시오.** 하나의 객체가 가장자리에서 출발해 안쪽으로 길게 뻗을 수 있습니다. 같은 이미지에서 덩어리 하나가 **시야의 19.7 %** 를 차지하며 왼쪽 변에서 정중앙까지 닿았고, 큰 것 두 개가 파란 면적의 75 %였습니다. 같은 색으로 이어져 있고 어딘가 가장자리에 닿아 있다면 전부 한 객체입니다. 넓으면 아래 '붙은 Pore가 하나로 뭉칠 때'를 보십시오.

### 명령줄 (배치 처리)

Windows:

```bat
CMP_PoreAnalyzer.exe --cli "C:\images\*.png" --csv result.csv --overlay-dir ov
CMP_PoreAnalyzer.exe --cli MID.png IN.png --threshold 0.45 --solidity 0.90 --sweep
```

macOS — 앱 번들 안의 실행 파일을 직접 호출하십시오:

```bash
CMP_PoreAnalyzer.app/Contents/MacOS/CMP_PoreAnalyzer --cli "*.png" --csv result.csv
```

주요 옵션: `--pixel-size` `--auto-pixel-size` `--sigma` `--threshold` `--mode` `--normalize`
`--min-diam` `--solidity` `--opening-radius` `--crop-top` `--crop-bottom` `--no-autocrop` `--keep-border` `--sweep`

## 4. 분석 조건

| 항목 | 기본값 | 설명 |
|---|---|---|
| 픽셀 크기 | 자동 | 메타데이터에서 읽거나 스케일바로 측정 |
| Gaussian σ | 1.2 px | 실질 판정 단위는 약 ±1.2 µm 이웃의 가중평균 |
| 이진화 임계 | 0.45 | 임계 모드가 '고정'일 때만 사용 |
| 임계 모드 | 고정 | 고정 / Otsu(이미지별) / Otsu(일괄) |
| 대비 정규화 | 꺼짐 | 이미지 간 밝기·대비 차이 상쇄 |
| 최소 등가직경 | 2.0 µm | 유효 최소 스케일 (0.404 µm/px에서 약 5 px) |
| Solidity 기준 | 0.90 | 이 값 이상만 개공률 분자에 포함 |
| Opening 반경 | 2 px | 폭 약 1.6 µm 미만의 가는 연결부 절단 |
| 상단 크롭 | 0 (자동) | 화면 캡처의 검은 여백 제거 |
| 하단 크롭 | 0 (자동) | SEM 정보바 제거 |
| 프레임 접촉 제외 | 켜짐 | 잘린 객체는 solidity를 신뢰할 수 없음 |

모든 항목은 **라벨에 마우스를 올리면** 의미와 산출식이 뜹니다. 결과 표의 열 제목도 마찬가지입니다.

### 이미지마다 밝기가 다를 때 — 임계 모드

같은 임계값 0.45라도 이미지의 밝기가 다르면 같은 기준이 아닙니다. 한쪽이 밝게 찍혔을 뿐인데 개공률 차이로 둔갑합니다.

합성 이미지로 확인한 결과입니다. 두 조건은 실제로 2.25배 차이가 나고, 한쪽(기공이 많은 쪽)을 밝고 대비 낮게 찍은 상황을 만들었습니다.

| 모드 | 밝기 동일 (참값) | 한쪽만 밝고 대비 낮음 |
|---|---|---|
| 고정 0.45 | 2.25배 | **1.73배** |
| 고정 + 대비 정규화 | 2.22배 | 2.22배 |
| Otsu (이미지별) | 2.24배 | 2.24배 |
| Otsu (일괄) | 2.24배 | 2.09배 |
| **대비 정규화 + Otsu (일괄)** | **2.24배** | **2.24배** |

**조건 간 비교에는 `대비 정규화 + Otsu(일괄)`을 쓰십시오.** GUI의 `권장 설정` 버튼이 한 번에 맞춰줍니다. CLI는 `--normalize --mode otsu-batch`입니다.

각 모드의 성격은 이렇습니다.

- **고정** — 입력한 값을 그대로 씁니다. 촬영 조건이 완전히 동일할 때만 안전합니다. 기존 논문 수치(고정 0.45)를 재현하실 때는 이 모드를 쓰셔야 합니다.
- **Otsu (이미지별)** — 이미지마다 임계값을 따로 정합니다. 밝기 차이는 사라지지만, 조건 간 실제 차이까지 일부 흡수할 수 있습니다.
- **Otsu (일괄)** — 불러온 모든 이미지의 밝기 분포를 합쳐 임계값 하나를 정하고 전부에 같게 적용합니다. 이미지 집합의 실제 밝기 범위에 맞추면서 비교 대상 간 기준은 동일하게 유지됩니다.
- **Otsu 3계급 (이미지별 / 일괄)** — 밝기를 **세 무리**로 나눈 뒤 가장 어두운 무리만 Pore로 봅니다. 아래를 보십시오.
- **대비 정규화** — 하위 1 %와 상위 99 % 밝기를 각각 0과 1로 보내 이미지별 gain/offset 차이를 상쇄합니다. 극단값 기준이라 기공 많고 적음에는 거의 흔들리지 않습니다. 대비가 아주 낮아도 늘려 펴는 배율을 제한하지 않습니다 — 제한해서 얻는 것이 없었습니다(대비 1/16 압축에서도 개공율 유지). 대비가 낮으면 고정 임계는 0 %로 무너지지만 이 옵션을 켜면 7.4 %로 복원됩니다.

Otsu 두 모드에서는 **`이진화 임계` 입력칸이 쓰이지 않습니다.** 그래서 모드를 바꾸면 그 칸이 회색으로 잠기고, 실제로 적용되는 값은 분석 조건 아래의 **`적용 임계`** 줄에 나옵니다. 실행 전에는 "분석 실행 후 결정", 실행 후에는 실제 값(일괄이면 하나, 이미지별이면 최솟값–최댓값)이 표시됩니다. 이미지별 값은 결과 표의 `적용 임계` 열에 있습니다.

**두 조건을 비교하실 때는 이 값이 서로 같은지 반드시 확인하십시오.** 다르면 개공률 차이에 임계값 차이가 섞여 있습니다.

#### 같은 파일을 넣는 순서가 달라도 결과는 같습니다

`Otsu(일괄)`은 모든 이미지의 히스토그램을 정확히 누적해 임계값을 뽑습니다. 이미지마다 무작위 표본을 뽑던 예전 방식은 넣는 순서에 따라 임계값이 흔들렸습니다. 합성 이미지에서 측정한 흔들림 폭입니다.

| 히스토그램 모양 | 순서에 따른 유효 개공율 변동 |
|---|---|
| 뚜렷한 이봉 | 0.5 % (상대) |
| 얕은 골 | 1.6 % |
| 거의 단봉 | **5.9 %** |

밝기 차이가 작아 골이 얕을 때 특히 컸습니다. 지금은 24가지 순서 전부가 동일한 값을 냅니다. 크기가 다른 이미지도 픽셀 수에 비례해 표를 행사하지 않도록 이미지별로 동등 가중합니다.

#### 대비가 낮거나 기공이 거의 없는 이미지 — `밝기 분리도`

Otsu는 **어떤 이미지를 줘도 임계값을 하나 내놓습니다.** 기공이 전혀 없는 시야를 줘도 노이즈를 둘로 갈라 개공율을 만들어냅니다. 합성 시험에서 기공이 0개인 이미지가 **5.0 %** 로 보고되었습니다.

그래서 결과 표에 진단 열 세 개를 추가했습니다.

| 열 | 뜻 | 판단 |
|---|---|---|
| `밝기 분리도` | Otsu의 계급 간 분산 ÷ 전체 분산 (0~1) | 실제 기공 0.90~0.94 / 기공 없음 0.64 / 정규화 붕괴 0.44. **0.70 미만이면 경고** |
| `동적 범위` | 정규화가 0과 1로 보내는 두 밝기의 간격 | 작아도 문제 아님 (0.546→0.031에서도 개공율 7.68→7.78 % 유지) |
| `계조 수` | 정규화 구간 안의 8비트 계조 개수 | **12단계 미만이면 경고.** 늘려 펴도 없는 정보는 생기지 않습니다 |

`밝기 분리도`는 대비를 1/16로 압축해도 0.939 → 0.938로 거의 변하지 않습니다. 즉 대비를 다시 말하는 값이 아니라, **두 계급이 실제로 있는지**를 보는 값입니다. 경고가 붙은 행은 표에서 주황색으로 표시되고 화면 위에 이유가 뜹니다.

> 0.70이라는 경계선은 합성 이미지에서만 확인한 값입니다. 실제 SEM 이미지 몇 장으로 분리도 값을 보시고 필요하면 조정하십시오.

### 밝기 무리가 셋일 때 — `Otsu 3계급`

마모된 패드 표면의 밝기는 두 무리가 아니라 셋인 경우가 많습니다. **깊은 Pore / 중간 회색 그림자 / 밝은 기지**입니다. 2계급 Otsu는 선을 하나만 그을 수 있어 **그림자와 기지 사이**에 놓이고, 그러면 중간 회색 그림자가 통째로 Pore로 분류됩니다.

실제 패드 이미지에서 측정한 결과입니다.

| | 임계 | 암부 | 최대 덩어리 | 파랑(접촉 탈락) | 유효 개공율 |
|---|---|---|---|---|---|
| Otsu 2계급 | 0.486 | 53 % | 시야의 19.7 % | 40.7 % | 3.15 % |
| **Otsu 3계급** | **0.359** | **33 %** | **2.6 %** | **6.0 %** | **5.25 %** |

눈으로 맞춘 값이 0.34였으니 3계급이 자동으로 거기에 근접합니다. `Otsu3(참고)` 열에 이 값이 항상 나오니, `Otsu(참고)`와 크게 벌어져 있으면 무리가 셋이라는 신호입니다. `밝기 분리도`가 0.70 아래인데 두 값이 벌어져 있다면 3계급을 먼저 시도하십시오.

**만능은 아닙니다.** 진짜로 두 무리뿐인 이미지에서는 과소평가합니다 — 참 암부 16.2 %인 합성 이미지에서 2계급은 16.3 %로 정확했지만 3계급은 13.3 %였습니다. 그래서 기본값이 아니라 모드로 둡니다. CLI는 `--mode otsu3` / `--mode otsu3-batch`.

### 객체화 방식 — 임계에 대한 종속 끊기

어두운 픽셀을 "하나의 Pore"로 묶는 방법은 임계값과 **별개의 결정**입니다. 기본값인 `연결 성분`은 이진화 마스크에서 이어진 픽셀을 한 객체로 보기 때문에, 임계가 조금만 높아 Pore 사이 회색이 암부에 들어오면 수십 개가 한 덩어리가 됩니다.

`지형 분할`은 회색 이미지 자체를 지형으로 봅니다. Pore 하나하나가 분지이고, `지형 깊이`보다 깊은 웅덩이를 씨앗으로 물을 채워 능선(리가먼트)에서 경계를 긋습니다. **그 능선이 임계값을 넘었는지와 무관합니다.**

실제 패드 이미지에서, 잘못된 2계급 임계를 **그대로 두고** 객체화만 바꾼 결과입니다.

| 객체화 | 최대 객체 | 프레임에 삼켜진 면적 | Pore 수 | 유효 개공율 |
|---|---|---|---|---|
| 연결 성분 | 시야의 19.7 % | 40.7 % | 112 | 3.15 % |
| 거리 분할 | 1.5 % | 9.7 % | 260 | — |
| **지형 분할** | **0.53 %** | **5.1 %** | 446 | 13.10 % |

임계를 3계급으로 바꾸고 지형 분할까지 쓰면 프레임에 삼켜진 면적이 3.1 %까지 내려갑니다.

**주의 1 — solidity 기준이 위험해집니다.** watershed 셀은 이웃과 맞닿은 면이 곧은 변이라 solidity가 체계적으로 낮아집니다. 같은 이미지에서 중앙값이 연결 성분 0.943 → 지형 분할 0.899로 내려가 기준 0.90에 겹쳤습니다.

| solidity 기준 | 유효 개공율 | 무효 |
|---|---|---|
| 0.80 | 36.93 % | 7.34 % |
| 0.85 | 27.31 % | 16.96 % |
| **0.90 (기본)** | **13.10 %** | 31.17 % |
| 0.95 | 3.07 % | 41.20 % |

446개 중 102개가 기준 ±0.02 안에 있습니다. 중앙값이 기준에 겹치면 프로그램이 경고합니다. 이때는 **절대값을 쓰지 마시고** 조건 간 대소 관계만 주장하시거나, `강건성 스윕`으로 순위가 뒤집히지 않는지 확인하십시오.

**주의 2.** 지형 분할은 객체 수를 크게 늘립니다(182 → 334개). 얕은 요철까지 각각 세기 때문입니다. `Pore 수`와 `밀도`를 조건 간 비교에 쓰신다면 `지형 깊이`를 양쪽에 똑같이 맞추셔야 합니다. `지형 깊이`는 밝기 단위(0~1)이지 길이가 아닙니다. CLI는 `--objectify terrain --terrain-depth 0.08`.

**지형 깊이가 하는 일.** 회색 이미지를 지형으로 보면 Pore는 웅덩이입니다. 두 웅덩이 사이에는 능선(리가먼트)이 있고, 깊이는 "웅덩이 바닥이 그 능선보다 이만큼은 낮아야 따로 센다"는 기준입니다.

```
밝기 ↑
 0.9 ┤        ╭──╮        ← 밝은 기지
     │   ╭────╯  ╰────╮
 0.5 ┤  ╱   능선 0.55  ╲
     │ ╱  ↕ h=0.08      ╲
 0.2 ┤╰─╯ 바닥 0.20  ╰─╯   ← 두 Pore의 바닥
     └──────────────────────→ 위치
```

바닥 0.20, 능선 0.55이면 깊이차가 0.35입니다. `지형 깊이`가 0.08이면 0.35 > 0.08이니 **따로 센 두 개**가 되고, 0.40이면 0.35 < 0.40이니 **하나로 합칩니다.** 그다음 두 씨앗에서 물을 채워 만나는 자리 — 능선 꼭대기 — 에 경계를 긋습니다.

핵심은 이 판단에 **이진화 임계가 끼어들지 않는다**는 점입니다. 능선이 임계를 넘었든 말았든 능선은 능선입니다.

**지형 깊이는 자동으로 정해지지 않습니다.** "이만큼은 깊어야 독립된 Pore"라는 기준이라 표면마다 다르고, 눈으로 고르셔야 하는 값입니다. `지형 깊이 비교…` 버튼을 누르시면 선택한 이미지를 여러 깊이로 분할해 나란히 보여 드리고, 마음에 드는 것 아래 `이 값 적용`을 누르면 분석 조건에 들어갑니다.

| 지형 깊이 | 유효 | 무효 | Pore 수 |
|---|---|---|---|
| 0.02 | 15.1 % | 30.0 % | 534 |
| 0.04 | 13.1 % | 31.2 % | 446 |
| **0.08 (기본)** | **9.5 %** | 33.9 % | 328 |
| 0.14 | 6.6 % | 33.7 % | 233 |
| 0.20 | 4.8 % | 32.9 % | 172 |

**이미지별로 따로 지정할 수도 있습니다.** 다만 대비 정규화를 켜두셨다면 깊이는 촬영 조건이 아니라 표면의 성질입니다.

| 변형 | 정규화 ON | 정규화 OFF |
|---|---|---|
| 밝게 +0.10 | 유효 +14 % | +4 % |
| 어둡게 −0.10 | ±0 % | −1 % |
| 대비 0.6배 | ±0 % | **−41 %** |
| 대비 1.4배 | +5 % | +15 % |

같은 깊이가 밝기·대비 변화를 그대로 통과하므로, **한 배치에는 한 값**이 정상입니다. 이미지 목록의 `지형깊이` 열에서 괄호 친 값은 기본값을 따르는 중이라는 뜻이고, 괄호가 없으면 그 이미지에만 따로 지정된 값입니다. 지정은 `지형 깊이 비교…` 창의 `이 이미지만` 버튼으로 합니다.

값이 섞이면 경고가 뜹니다. 깊이가 다르면 "Pore 하나"의 정의가 이미지마다 달라지므로, 표면이 정말 다른 경우에만 쓰십시오.

### 좁은 목으로만 붙어 있을 때 — `거리 분할`

거친 표면에서는 asperity 사이 그림자가 가느다란 어두운 다리를 만듭니다. 눈으로는 분명히 따로인 Pore들이 이진화 후에 한 덩어리로 이어지고, 그러면 세 가지가 한꺼번에 일어납니다.

1. 개별 Pore로 **객체화되지 않습니다**
2. 덩어리가 심하게 오목해져 **무효**로 분류됩니다
3. 덩어리가 프레임에 닿으면 **통째로 탈락**해 화면에서 사라집니다

실제 패드 이미지에서 한 덩어리가 시야를 가로질러 암부의 34 %를 차지하고 solidity 0.50으로 나온 적이 있습니다.

> **임계값을 먼저 보십시오.** 같은 이미지에서 연결부의 목 너비를 재보니 중앙값 10 px, 하위 10 %도 4.5 px였습니다. 가느다란 다리가 아니라 넓은 회색 영역이라는 뜻이고, 그건 연결성 문제가 아니라 이진화 문제입니다. 레버 효과(최대 덩어리 기준): 임계 0.486→0.34면 19.7 %→0.26 %, σ 1.2→0.4면 8.7 %, opening 2→4면 6.7 %, 8연결→4연결은 19.2 %로 거의 변화 없음. **대각선 연결은 원인이 아닙니다.** 임계(3계급 모드 포함)로 해결되지 않고 남은 뭉침에만 이 옵션을 쓰십시오.

`거리 분할`은 거리변환의 봉우리에서 물을 채워 목이 가장 좁은 곳에서 자릅니다(watershed). `분리 깊이 (µm)`가 "옆 봉우리보다 이만큼은 깊어야 따로 센다"는 기준입니다. µm 단위라 배율이 달라도 같은 물리적 기준입니다. CLI는 `--objectify distance --split-depth 2.0`.

**기본은 꺼져 있습니다.** 무엇을 Pore 하나로 볼지를 바꾸는 옵션이라 절대값이 크게 움직입니다.

| 분리 깊이 | 유효 Pore 개공율 |
|---|---|
| 끔 | 4.4 % |
| 0.5 µm | 19.3 % |
| 1.0 µm | 12.3 % |
| 2.0 µm | 10.0 % |

같은 이미지입니다. 비교하실 두 조건에 반드시 같은 값을 쓰시고, 논문에는 깊이를 병기하십시오.

> 뭉침이 심하다면 임계값도 함께 보십시오. 임계가 높으면 그림자까지 암부에 들어와 뭉침을 만듭니다. 어떤 실제 이미지에서 Otsu는 0.53을 골랐지만 눈에 보이는 Pore와 맞는 값은 0.34였고, 그때 `밝기 분리도`가 0.69로 경고 범위였습니다.

#### 대비 정규화에서 주의할 조합

하위 기준(1 %)이 **실제 암부 면적보다 크면** 그 백분위가 밝은 기지 안에 들어앉습니다. 그러면 기지의 노이즈가 0~1로 늘려 펴지고 기공은 전부 0으로 눌립니다. 기공이 0.5 %뿐인 시야에서 참값 0.41 %가 **5.16 %** 로 나온 적이 있습니다.

프로그램이 먼저 암부 비율을 어림하고 필요하면 하위 기준을 그 아래로 자동으로 낮춥니다(위 예에서 1.00 % → 0.24 %, 결과 0.413 %). 낮췄을 때는 경고로 알려 드립니다. 암부가 3 % 이상인 통상적인 이미지에서는 발동하지 않으므로 **기존 결과는 그대로입니다.**

논문에 쓰실 때는 모드와 적용 임계값을 함께 밝히십시오.

> 이미지 간 밝기 차이를 보정하기 위해 하위 1 %–상위 99 % 밝기를 기준으로 대비를 정규화한 뒤, 비교 대상 전체의 밝기 분포에서 Otsu 법으로 산출한 단일 임계값(0.5115)을 모든 이미지에 동일하게 적용하였다.

### 픽셀 크기 — 직접 계산하실 필요 없습니다

두 가지 경로가 있습니다.

**1. 파일 메타데이터에서 자동 추출.** 이미지를 추가하면 자동으로 읽어 채웁니다. Zeiss(`Image Pixel Size`), FEI/Thermo(`PixelWidth`), ImageJ(`unit=` + 해상도 태그), 일반 TIFF 해상도 태그, Hitachi 사이드카 `.txt`를 지원합니다. 어디서 읽었는지 옆에 표시됩니다.

**2. 스케일바 측정.** 화면 캡처나 JPEG처럼 메타데이터가 없으면 `스케일바로 측정…` 버튼을 누르십시오. 원본 전체(정보바 포함)가 뜨므로 하단 스케일바가 그대로 보입니다. 바의 양 끝을 드래그하고 거기 적힌 길이를 입력하면 계산됩니다.

- **확대경**이 커서 주변을 7배로 보여주어 끝점을 정확히 찍을 수 있습니다
- **수평 고정**(기본 켜짐)으로 위아래 흔들림이 길이에 섞이지 않습니다
- 메타데이터가 있으면 측정값과의 차이를 표시해 교차 검증됩니다
- 20픽셀 미만으로 짧게 지정하면 경고합니다. 짧을수록 한두 픽셀 오차가 그대로 비율 오차가 됩니다

픽셀 크기는 면적·등가직경·밀도·개공률에 비례해 영향을 줍니다. 형상 지표(원형도·solidity)는 영향을 받지 않습니다.

### 여러 파일을 한 번에 올릴 때

- **파일 이름이 겹쳐도 구분됩니다.** `cond_A/site01.tif`와 `cond_B/site01.tif`처럼 폴더가 다른 동명 파일은 표·CSV·오버레이 파일명에 폴더명이 함께 붙습니다. CSV에는 전체 경로가 담긴 `path` 열도 있습니다.
- **한 파일이 실패해도 배치는 계속됩니다.** 손상된 파일이 있으면 그 파일만 건너뛰고, 끝에 한 번만 요약 경고가 뜹니다. 실패한 파일은 결과와 CSV에서 제외됩니다.
- **측정한 픽셀 크기는 다음 실행에도 남습니다.** 스케일바로 재거나 직접 입력한 값은 파일 경로를 키로 저장되어, 프로그램을 다시 켜도 복원됩니다. 메타데이터에서 읽은 값은 저장하지 않습니다(다시 읽으면 되고, 파일이 바뀌면 옛 값이 오히려 위험하기 때문입니다).
- **메모리.** 미리보기 오버레이는 긴 변 1000 px로 줄여서 보관합니다. 2048×1536 이미지 기준 장당 9 MiB → 2.1 MiB로, 12장에서 상주량이 108 MiB에서 26 MiB로 줄었습니다. `오버레이 저장`은 그 이미지만 다시 계산해 **원본 해상도로** 저장합니다.

### 배율이 서로 다른 이미지를 섞을 때

**이미지마다 픽셀 크기를 따로 가집니다.** 파일 목록이 표로 되어 있어 각 이미지의 `µm/px`와 그 출처가 보입니다. 메타데이터에서 자동으로 채워지고, 행을 더블클릭하면 직접 입력하거나 스케일바로 측정할 수 있습니다. 값을 모르는 이미지는 `기본값 사용`으로 표시됩니다.

배율이 섞이면 목록 아래에 경고가 뜹니다.

**픽셀 크기가 무엇에 영향을 주는지**는 분명히 구분해 두십시오.

| 항목 | 영향 |
|---|---|
| 개공률 | **거의 없음.** 분자와 분모가 모두 픽셀 크기의 제곱으로 스케일되어 상쇄됩니다. 최소 등가직경(µm) 필터를 통해서만 간접적으로 작용합니다 |
| 등가직경·밀도·시야 | **직접 비례해서 달라집니다** |
| 원형도·Solidity | 없음 (무차원) |

최소 등가직경 필터를 끄고 확인하면 0.101 µm/px든 0.808 µm/px든 개공률이 7.0745 %로 동일합니다.

**σ·opening을 µm로** 옵션은 평활과 opening이 배율과 무관하게 같은 물리적 거리를 덮게 합니다. σ = 1.2 px는 0.404 µm/px에서 0.485 µm이지만 0.101 µm/px에서는 0.121 µm라, 같은 숫자가 전혀 다른 크기가 되기 때문입니다.

> 이 옵션이 보장하는 것은 **필터 기준의 일관성**이지, 배율이 다른 두 이미지의 개공률이 반드시 더 가까워진다는 뜻은 아닙니다. 합성 이미지 시험에서 어떤 경우엔 차이가 0.27 → 0.07 %p로 줄었지만 다른 경우엔 0.27 → 0.28 %p로 거의 그대로였습니다. 업샘플링은 실제 고배율 촬영의 대역을 재현하지 못하므로 그 시험 자체의 한계이기도 합니다. **가능하면 비교 대상은 같은 배율로 촬영하십시오.** 이 옵션은 그러지 못했을 때의 차선책입니다.

### 단색 띠 자동 크롭

이미지 위아래의 단색 띠(SEM 정보바, 화면 캡처의 레터박스)를 찾아 잘라냅니다. **잘라내지 않으면 그 띠가 시야 면적에 그대로 들어가 개공률의 분모를 키우므로, 값이 실제보다 낮게 나옵니다.**

위 150 px / 아래 70 px의 검은 띠를 붙인 테스트 이미지에서 확인한 값입니다.

| | 개공률 | 시야 |
|---|---|---|
| 크롭 없음 | 3.94 % | 357 × 339 µm |
| 자동 크롭 | **5.34 %** | 357 × 250 µm |
| 띠가 없는 원본 | 5.34 % | 357 × 250 µm |

띠가 크게 잡혀 있으면 결과 표의 `접촉면적 %`가 비정상적으로 큽니다(위 예에서 26.2 %). 그 값이 의심스러우면 크롭부터 확인하십시오.

거의 단색이면서 흑/백 극단에 가까운 띠만 인정하는 보수적인 판정이라, 실제 패드 표면을 잘라낼 위험은 낮습니다. 크롭 값을 직접 입력하시면 자동 감지보다 우선합니다.

## 5. 해석 시 유의사항

- **프레임 접촉 객체 제외로 개공률은 과소평가됩니다.** 큰 객체일수록 프레임에 닿을 확률이 높기 때문이며, 제외된 면적 비율을 결과에 함께 표시합니다. 논문에 한 줄 밝히시는 것이 정직합니다.
- **"개공률"은 표준 용어와 다른 조작적 정의입니다.** 정의를 병기하지 않으면 독자가 전체 암부면적률을 기대하고 읽습니다.
- **조건당 시야 1장은 부족합니다.** 한 시야 안의 객체들은 공간적으로 상관되어 있어, 객체를 표본 단위로 삼은 신뢰구간은 실제보다 좁습니다. 조건당 5시야 이상 확보하신 뒤 시야를 단위로 다시 계산하시는 것이 안전합니다.
- 분할된 어두운 영역에는 노출된 기공과 표면 그림자가 함께 포함됩니다.

`pore_analyzer/core.py`의 `bootstrap_median_diff()`로 두 조건의 중앙값 차이에 대한 95% 신뢰구간을 구할 수 있습니다. 위 한계가 그대로 적용되므로 주의해서 사용하십시오.
